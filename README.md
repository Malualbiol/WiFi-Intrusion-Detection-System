# Machine Learning Wi-Fi Intrusion Detection System (Windows)

## Scope and honesty about results
This is a **working offline, CSV-replay WIDS prototype**, not a real-time radio sniffer. It runs safely with no attack transmission and needs no special Wi-Fi adapter. The bundled dataset is **SYNTHETIC**, generated by `wids.py generate`; results based on it are useful to verify the pipeline but are **not proof of real-world performance**. Before claiming performance on real traffic, replace it with labelled authorised capture data or a suitably converted public dataset (e.g. AWID3). No claim that AWID3 has been evaluated here.

## Windows setup (step by step)
1. Install Python 3.11 or 3.12 from python.org; during setup select **Add Python to PATH** and install the Python launcher.
2. Extract the ZIP and open the `wids_windows_project` folder.
3. Double-click `run_windows.bat`. It makes a local virtual environment, installs dependencies, creates synthetic data, trains, evaluates and replays the demonstration.
4. Watch console output for `NORMAL` and `ALERT: DEAUTH FLOOD`.
5. Open `results/confusion_matrix.png`, `results/metrics.json`, and `results/alerts.csv`.

### Alternative: Windows PowerShell
Open PowerShell in the project folder:

```powershell
py -3 -m venv .venv
```

## CSV schema and real-data pathway
`wids.py train --csv path\to\your_authorised_frames.csv` and `wids.py demo --csv path\to\your_authorised_frames.csv` accept CSV columns:

| column | meaning | example |
|---|---|---|
| timestamp | ISO 8601 capture timestamp | `2026-10-01T09:00:00.100Z` |
| src_mac | observed transmitter MAC | `02:11:22:33:44:55` |
| frame_type | `management`, `data`, `control` | `management` |
| subtype | `deauth`, `beacon`, `ack`, etc. | `deauth` |
| rssi_dbm | numeric received signal strength; blank allowed | `-62` |
| label | **0** normal or **1** actual deauth flood | `1` |
| session_id | capture/run identifier for leakage-resistant splitting | `capture_attack_03` |

This schema is **our project's input format, not the native format of AWID3**. An AWID3 adapter/conversion and reliable ground-truth labels are needed first; merely renaming columns is not enough. For labelled runs, assign session IDs so a test capture/run is not also included in training. If frames from multiple sources are mixed in one second, the program aggregates by `(session_id, src_mac, second)`. The label in each window is 1 when any included frame has label 1.

Important: `src_mac` is reported in an alert, but not used as a predictive feature. A frame's claimed source MAC can be forged. The WIDS does not block any devices.

## Feature extraction and training
- Each transmitter's frame records are grouped into one-second windows.
- Features: number of frames per second; deauthentication frames per second; deauthentication ratio; mean RSSI in dBm; proportion of management frames.
- Model: scikit-learn RandomForestClassifier with 100 trees, maximum depth 7, fixed seed 42.
- Splitting: GroupShuffleSplit (75% training / 25% test **by session**, not row) to reduce leakage from adjacent windows within the same run.
- Outputs: accuracy, precision/recall/F1, confusion matrix PNG, JSON metrics, and serialised model.
- In the synthetic benchmark, attacks were deliberately made much more intense than normal traffic, so very high accuracy is expected. Do not generalise.

## Expected synthetic run (fixed seed)
- 35,996 generated frame records; 1,080 aggregate windows.
- 804 train and 276 test windows; accuracy 100%.
- Confusion matrix in `[Normal, Deauth flood]` row/column order: `[[156,0],[0,120]]`.
- This benchmark has no false positives or false negatives **on this synthetic holdout only**.

## Troubleshooting
- `py is not recognized`: install Python with the launcher from python.org, then reopen PowerShell.
- `No module named sklearn`: use the `.venv\Scripts\python.exe` executable, not an unrelated Python installation.
- `FileNotFoundError`: run `generate` before `train` and `train` before `demo`.
- `ValueError Missing CSV fields`: use the schema shown above.
- 100% accuracy on synthetic data is not evidence that it will work with unseen real captures.
